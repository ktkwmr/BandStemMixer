# 記事の内容確認（人間がやる）

記事は Claude が書き、**公開（main へのマージ）の前に人間が内容を確認**します（WEBAPP_BASELINE.md §10-7）。
PR を出すと Cloudflare のプレビュー URL ができるので、そこで実際のページを見て確認します。直したい点は PR のコメントか Claude への指示で伝えてください。

## 毎回見ること

| # | 観点 | 見るところ |
|---|---|---|
| 1 | 事実の正しさ | 分野の説明に間違いや言い過ぎがないか |
| 2 | アプリとの一致 | 記事の説明（ボタン名・手順・条件）がいまのアプリの動きと合っているか。画面写真が古くないか |
| 3 | 表の内容 | 数字（モデルの大きさ・曲の長さの上限・フェーダーの上限・MP3 のビットレート・区間の数）はアプリのファイルから読んでいる（`scripts/pages/app.mjs`）ので書き間違いはないが、選んだ例が自然か |
| 4 | 日本語・英語の自然さ | 直訳っぽい言い回し、用語の不統一 |
| 5 | 検索用の文言 | 各記事の `title` と `description`（`scripts/pages/<slug>.mjs` の先頭）が、狙う検索語を含み、内容と合っているか |
| 6 | 権利 | 著作権のある歌詞・曲・画像を使っていないか（画面写真の曲は `scripts/guide-song.mjs` で作った架空の曲） |
| 7 | スマホ | 390px 前後の幅で読みやすいか |

## 今回（2026-10-29、最初の記事 6 本）特に見てほしいところ

記事: `guide`（使い方）・`minus-one`（自分のパートを消して練習）・`learn-by-ear`（ベースとドラムを聞き取る）・`how-it-works`（AI 音源分離の仕組み）・`better-results`（うまく分離するコツ）・`faq`（よくある質問）。

| # | 記事 | 確認してほしい点 |
|---|---|---|
| A | guide・faq | 分離にかかる時間「最近のパソコンで曲の長さと同じくらいから数倍」は、アプリの説明文と同じ目安。実際の PC・スマホでの時間と合っているか |
| B | guide | 進み具合の画面写真は、AI モデルの代わりの仮の処理で撮ったもの（区間の数と残り時間の表示は本物と同じ計算）。分離の結果の音は架空の曲のパートそのもので、本物の分離の音ではない |
| C | faq | 「一度分離すると、通信がなくても開いて分離できる」は仕組み上そうなる（アプリ・AI モデル・ONNX Runtime をキャッシュ）が、機内モードでの実機確認はしていない |
| D | minus-one・learn-by-ear | 練習方法のコツ（ベースはキックに合わせる、ルート音から取る、自分のパートを 20〜30% 残す など）は一般的な練習法。演奏者の立場で違和感がないか |
| E | minus-one・faq | 「コーラス・ハモリはふつうボーカルに入る」「ドラムにはタンバリンなどの打楽器も入る」は、学習データ（MUSDB）の分け方からの推測で、Demucs の文書に明記はない。言い切りを避けた |
| F | better-results | 「128 kbps 以下は分離したパートにシャリシャリした音が出やすい」「ステレオのほうが分離しやすい」は一般的な知見で、Demucs の文書に数値はない |
| G | minus-one・faq | 権利の説明（自分の練習のための分離と、公開・配布は別。公開にはふつう許可が必要）。法的な言い切りは避けた |
| H | learn-by-ear | 同じサイトの Loop Trainer（/looptrainer/）へのリンク。プレビューでは別の Worker なので開けない（本番では開ける） |

3. 公開後、Search Console でサイトマップ（`https://ktkwmr.com/bandstemmixer/sitemap.xml`）を再送信する。
